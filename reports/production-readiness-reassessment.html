三、改进成果总结（八阶段回顾）

Eight-Phase Improvements
PHASE 1
紧急 Bug 修复
Com.c uint8 溢出、WdgM 活跃监督、NvM 缺失 API、E2E Init/DeInit。
PHASE 2
重复模块收敛
7 对重复模块收敛（tombstone shim 策略，移除 --allow-multiple-definition）。
PHASE 3
BswM 增厚
PDU Group、优先级、脏标志、EcuM 协调、RuleEnable/Disable → 292 LOC → 890 LOC。
PHASE 4
CAN 栈加固
PN 过滤、O(1) Rx 查表、Tx 重试队列、CanSM PNSA、CanTp 填充验证。
PHASE 5
CI 硬化
移除所有 continue-on-error / || echo / || true，修复 MISRA 正则假阳性根因。
PHASE 6
配置生成
JSON Schema + 7 个 Jinja2 模板 + 编排脚本 + CMake 自动重生成 + CI 漂移检测。
PHASE 7
安全合规
ISO 26262 GSN 安全案例、验收矩阵 36% → 100%、ISO 21434 网络安全案例骨架。
PHASE 8
P1 测试基础设施
性能基准 3 套、NvM CRC 查表、Com memcpy 快速路径。

四、新发现的 P0 问题（阻塞量产）

Newly Identified P0 Blockers

P0-NEW-14 对新发现的重复模块未收敛

  • services/canm vs ecual/canNm（CanNm_Init 冲突）
  • services/linsm vs ecual/linSM（LinSM_Init 冲突）
  • mcal/fee vs ecual/fee（Fee_Init 冲突）
  • services/ramtst vs mcal/ramtst（RamTst_Init 冲突）
  • 这 4 对未在 CMake 中做 shim 排除，两侧都编译真实实现，链接时会产生符号冲突或 ODR 违规。

P0-NEW-2FvM（新鲜值管理）仅 QEMU 存根

  • Cdd_Fvm_1.0.0.c 为 QEMU 存根，缺乏生产级新鲜值同步。
  • SecOC 量产依赖 FvM，这是安全通信的必要条件。

P0-NEW-3安全案例模块审查证据缺失

  • .osh/evidence/reviews/ 目录为空。
  • Safety Case 声称 13 个模块通过审查，但无任何证据文件。
  • ISO 26262 审计将此视为不合格项。

五、P1 问题清单

P1 Issue List

P1-1MISRA error 级违规 51 项

  • 集中在 ComM.c 和 CanNm.c，应为零。
  • CI 门禁 fail_on_required 对 MISRA error 仍未完全硬化。

P1-2143 个 TEST_IGNORE 存根测试

  • 声明了 API 存在但无真实断言逻辑。
  • 虚增测试数量，实际有效测试覆盖低于名义值。

P1-3分支覆盖率门禁过低

  • CI 门禁：40% 行覆盖 / 25% 分支覆盖。
  • 汽车行业标准：80%+ 行 / 70%+ 分支。
  • ASIL 关键模块 91.57% / 79.79% 仅覆盖 15 个文件。

P1-46 个 CI 作业永久跳过

  • E2E-DDS、UDS、OTA、Multi-ECU、Performance、Security 测试作业因二进制不存在而跳过。
  • 性能基准已有但 CI 期望的二进制名称不匹配。

P1-5缺少量产 MCU 的完整 MCAL 实现

  • MCAL 驱动多为框架/mock 实现。
  • 缺少 S32K312 或 TC3xx 的完整外设驱动。

P1-6配置覆盖率仅 16%

  • 17/104 模块有 JSON 配置 + Jinja2 模板。
  • Crypto、Eth、CanSm、ComM 等关键模块缺失。

P1-7SecOC Freshness 持久化不完整

  • 仅使用简单计数器，缺少与 NvM 的持久化同步。
  • 不支持硬件 TRNG。

P1-8API 文档仅覆盖 3 个模块

  • docs/api/ 仅有 Com、Crypto、DCM 的 API 参考。
  • 缺少 OEM/第三方集成指南。

P1-9MC/DC 覆盖率未测量

  • ASIL B 至少需要分支覆盖，ASIL D 需要 MC/DC。
  • VERIFICATION_REPORT.md 坦诚记录"MC/DC 未测量"。

P1-10需求可追溯矩阵不一致

  • docs/requirement-traceability-matrix.md 仅 17 行。
  • Safety Case 声称 127 个 SHALL 条目。

P1-11ISO 21434 三条款缺失

  • Clause 7（分布式活动）、Clause 8（持续监控）、Clause 11（漏洞管理）标记为"待建"。

P1-12DoIP 全链路联调不足

  • DoIP + SoAd + TcpIp + Dcm 集成测试缺失。

P1-13CAN FD 支持不完整

  • CanIf/CanTp 的 CAN FD 规范支持有限。

九、结论

Conclusion
  • 从 C+ (3.0) 提升至 B- (3.5)，TRL 5-6 → TRL 6-7。
  • 八阶段改进有效提升了工程规范性，特别是 CI、配置工具链、安全合规。
  • 距离 SOP 量产（TRL 8-9 / A- / 4.5+）仍有显著差距。
